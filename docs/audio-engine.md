# Audio engine

`src/engine` owns every audio fact. See `docs/architecture.md` for how the UI reads it.

## Graph

`buildGraph(ctx, params, irBuffer)` builds the same topology for live playback and for
offline export, so the exported file matches what you heard:

```
  source --> input --> bass shelf --> warmth low-pass --> drive --+--> dry (1 - mix) --+--> master --> destination
    ^                                                             +--> convolver --> wet (mix) --+     |     ^
    | detune                                                                                          v     |
  wobble LFO (0.8 Hz sine) --> depth gain                          crackle source (loop) --> crackle gain --+  analyser
                                                                                                    (live only)
```

`mix = reverbLevel / 100`, `master = volume / 100`. The tone chain sits before the
reverb split so the room hears the coloured signal: `bass` is a low shelf at 110 Hz
lifted by up to 9 dB; `warmth` is a low-pass whose cutoff falls exponentially from
20 kHz (0) to 1.2 kHz (100) at Q 0.707; `drive` is a `WaveShaperNode` with a
unity-gain `tanh` curve whose slope grows from 1 to 8 (`null` curve at 0, so it is
bit-transparent) and 2x oversampling; `wobble` is one sine LFO into a depth gain
that the engine connects to every source's `detune`, up to 25 cents. All four are
in `buildGraph`, so the export renders them too. The impulse response and the
crackle bed are generated by `synth.ts` for the context that plays them, so nothing
is fetched and the sample rates always match. The crackle is a looping
`AudioBufferSourceNode` under its own gain (`vinylVolume / 100`); it starts with
play, survives seeks, stops with pause, and is excluded from export. The analyser
hangs off the master bus for `getLevel()` only.

## State machine

```
  idle --load--> loading --ok--> ready --play--> playing
                    |                              |  ^
                    |                       pause / |  | play
                    |                    natural end v  |
                    +--fail--> (previous)          paused
```

- `load()` failure returns to `idle` (no previous track) or `paused` (previous track
  and its params intact), with `error` set in the snapshot.
- `load()` resets the position to 0 and clears `loopStart`/`loopEnd`, because loop
  points are seconds of a particular track.
- Natural end stops **and disconnects** the node, then parks at `paused`, position 0.
- `getLevel()` is the RMS of a 256-sample window on the master bus, scaled by 3 and
  clamped to 1; it is 0 unless `playing`. The UI polls it per frame for the mark next
  to the track title, never through React state.
- `seek()` while playing rebuilds the source node at the new offset and stays
  `playing`; while paused it only moves the playhead.

## Params and units

| field                   | range             | applied to                         |
| ----------------------- | ----------------- | ---------------------------------- |
| `volume`                | 0..110 (%)        | master gain                        |
| `playbackRate`          | 0.65..1.35        | source node, also shifts pitch     |
| `reverbLevel`           | 0..100 (%)        | wet/dry crossfade                  |
| `vinylVolume`           | 0..100 (%)        | crackle gain                       |
| `bass`                  | 0..100 (%)        | low-shelf gain, 0..9 dB            |
| `warmth`                | 0..100 (%)        | low-pass cutoff, 20 kHz..1.2 kHz   |
| `drive`                 | 0..100 (%)        | wave-shaper slope, 1..8            |
| `wobble`                | 0..100 (%)        | LFO depth on `detune`, 0..25 cents |
| `loop`                  | boolean           | live source node                   |
| `loopStart` / `loopEnd` | seconds or `null` | live source node                   |

Every change is written to the _live_ nodes; nothing is rebuilt for a slider move.

## Loop rules

`resolveLoopRegion(start, end, duration)` clamps both points into `[0, duration]` and
falls back to the whole track when either is `null` or `start >= end` — the same
condition the Web Audio spec uses to ignore loop points. A non-custom region is
written to the node as `loopStart = loopEnd = 0`, the spec's "loop the whole buffer".

Three rules follow from how `AudioBufferSourceNode` actually behaves:

1. **Intro once, then loop.** Starting below `loopStart` plays forward and wraps the
   first time the playhead reaches `loopEnd`.
2. **Never start at or past `loopEnd`.** A looping node started there plays the tail
   once and then emits silence forever, with no `ended` event. `startSource()` clamps
   such an offset to `loopStart`.
3. **A moved region needs a restart.** Writing new loop points onto a live node cannot
   rewind it. If the region changes while the playhead is at or past the new end, the
   engine restarts the node at the new start. Every other param change is a live write.

## Position

A `requestAnimationFrame` loop runs only while `playing`. Each frame it integrates the
delta of `context.currentTime` through the pure `advancePosition()`, which clamps a
negative delta, carries the overshoot across a loop wrap, and reports `ended`. The
node's own `ended` event is deliberately unused: one owner per fact, and `ended` also
fires for stops the engine itself issues.

Position is not React state. At 60 fps it would re-render the tree 60 times a second
for a number only the canvas needs; it travels as a `tick` event instead. When the
window is hidden rAF stops firing, and the first frame after it returns sees one large
delta and lands on the right position.

## Export

`exportWav()` renders offline: an `OfflineAudioContext` with the track's channel count
and sample rate, `ceil(track.length / playbackRate)` frames, the same `buildGraph`,
`source.start(0)`, then `audioBufferToWav()` to 16-bit PCM RIFF. Vinyl is excluded and
loop points are ignored — a single pass of the whole track. The engine returns the
Blob; `usePlayer()` names it `<track without its extension>-lofi.wav` (`exportFileName`)
and hands it to `downloadBlob()`.

## Peaks

`computePeaks(channelData, columns)` returns `columns * 2` interleaved `[max, min]`
floats, normalised so the loudest sample sits at 0.95. Block bounds come from
fractional offsets (`floor(i * len / columns)` to at least `start + 1`), which fixes
the old `blockSize = floor(len / width) === 0` case where any buffer shorter than the
canvas drew solid full-height blocks, and stops the tail samples being dropped.

It runs on the **main thread**, once per track and column count, and the result is
cached (cleared on `load()`). One pass over a 5-minute track is tens of milliseconds,
right after a decode that took far longer.

A Web Worker version bundles under `next build` but not under `next dev --turbopack`,
which prefixes worker chunk URLs with the absolute dev `assetPrefix` twice. `getPeaks()`
stays `async` so the worker can return once the dev `assetPrefix` is relative.

## Memory

`decodeAudioData` keeps the whole track as float32 PCM: **~21 MB per minute** of
stereo 44.1 kHz audio (5 minutes ≈ 106 MB), plus a transient copy of one channel for
the peaks and, during export, the rendered buffer. Accepted for now; streaming decode
would mean giving up instant seeking.

## WebKitGTK notes

An `AudioContext` starts `suspended` under autoplay policy, so `resume()` is awaited
inside the gesture that triggered it (`load()` from picking a file, `play()` from the
button). Playback, export and drag-and-drop work in the `.deb` on Ubuntu 24.04 GNOME;
a WebKitGTK drop announces files only through `DataTransfer.types`, which `useFileDrop` reads first.

## Generated sounds

`synth.ts` builds both beds from a seeded generator (Mulberry32), so they are
identical on every run and in tests. The impulse response is 2.4 s of white noise
through a one-pole low-pass whose cutoff falls over time, under an `exp(-6 t)`
envelope, after 12 ms of pre-delay: a large, soft room that darkens as it fades. The
convolver normalises its loudness. The crackle is 6 s of band-limited hiss at
-29 dB with about 14 random pops per second, a few of them larger; the hiss is
stationary, so the loop has no seam. Nothing under `public/` is audio, and the app
has no runtime asset loads.
